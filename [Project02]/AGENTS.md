# Project02 작업 지침

상위 지침과 사용자의 최신 결정을 우선한다. 아래 내용은 `[Project02]` 작업에만 적용한다.

## 먼저 읽을 문서

- `README.md`, `documents/FEATURE_SPEC.md`, `documents/DATA_CONTRACTS.md`.
- 구현·검증 작업이면 `documents/ARCHITECTURE.md`, `documents/HARNESS_PLAN.md`, `documents/IMPLEMENTATION_CHECKLIST.md`도 읽는다.
- 미정 사항은 `documents/OPEN_DECISIONS.md`에서 확인한다. 초안의 제안값을 사용자가 확정한 요구로 바꾸지 않는다.

## 범위와 변경 보존

- 현재 요청은 **설계 문서 작성**이다. 별도 구현 요청 전에는 실행 코드, 의존성 설치, 하네스 실행 파일을 만들지 않는다.
- Project01, 강의 노트북, 루트 학습 스크립트·데이터, 진행 중인 학습을 이 프로젝트 작업 때문에 수정·중단하지 않는다.
- Mac은 학습·개발용이고 최종 장치는 Jetson이다. Mac에서 통과한 테스트를 Jetson 장치 검증으로 기록하지 않는다.
- 새 모델 다운로드·추가 학습·TensorRT 변환·GitHub 업로드는 현재 요청 범위에 포함됐는지 확인한다. 매번 재승인받을 필요는 없지만 이전의 다른 작업 권한을 이 프로젝트 전체로 확대하지 않는다.

## 제품 동작

- 음성 입력은 키·버튼 없이 연속 감지한다. 대기 중 음성 시작을 감지하면 녹음하고, 말이 끝나면 해당 구간만 STT로 전달한다. 처리·TTS 재생 중에는 새 입력을 실행하거나 대기열에 쌓지 않고, 끝난 뒤 오래된 입력을 버리고 음성 대기로 돌아간다.
- 사용자의 음성 질문에서 메뉴 추천 의도를 인식한 경우에만 추천 작업을 시작한다.
- `냉장고에 식재료 뭐뭐 있어?` 같은 재료 조회는 현재 사진을 촬영해 YOLO와 필요한 경우의 VLM 확인까지만 수행한다. 같은 재료는 한 번만, 개수 없이 한국어 종류명으로 안내한다. 메뉴 추천·추가 구매 제안·식사 기록 읽기와 갱신은 하지 않는다.
- 식재료 확인 질문을 끼워 넣지 않고 바로 추천한다. 인식 실패 시 재촬영 안내는 가능하다.
- YOLO의 confidence가 충분히 높은 재료는 바로 사용하고, 애매한 후보가 있을 때만 Gemma VLM으로 확인한다. 애매한 영역들을 한 이미지로 모아 한 번만 호출한다. 모든 후보가 확실하면 VLM 이미지 분석을 생략한다. Gemma의 텍스트 메뉴 추천은 메뉴를 물었을 때만 수행한다. 실제 VLM 연동 검증에는 애매한 후보가 있는 사진을 사용한다.
- 탐지 하한과 바로 사용할 confidence 기준은 실제 사진으로 정한다. VLM이 확인하지 못한 후보는 제외하고, 이미 확실한 재료는 유지한다. YOLO가 아예 놓친 재료를 이 과정에서 찾아낸다고 설명하지 않는다.
- YOLO 기본 경로는 Project02 루트의 `ingredients_int8.engine`이다. 진입점에서 프로젝트 루트를 계산해 어댑터에 전달하고 실행 터미널의 현재 폴더에 의존하지 않는다. 파일이 없으면 명확하게 실패 처리하며 기본 COCO 모델로 자동 대체하지 않는다. `ingredients_int8_raw.engine`은 측정용이므로 앱 모델로 쓰지 않는다.
- Gemma는 자유롭게 메뉴를 생성한다. 고정 메뉴 목록·레시피 DB를 필수 구성으로 추가하지 않는다.
- 추천 이벤트 동안 안내한 메뉴 이름 전체와 마지막 안내 목록만 메모리에 유지한다. `딴 메뉴 없어?`는 그 이벤트에서 이미 안내한 메뉴를 제외해 다시 제안한다. 메뉴 선택 저장 성공·명시적 종료·취소·후보 없음·새 일반 추천·프로그램 종료 때 임시 목록을 비우며, 파일에 추천 이력을 쌓지 않는다.
- 메뉴 추천은 최대 2개이며, 1개면 `추천 메뉴는 A입니다.`, 2개면 `추천 메뉴는 A, B입니다.`로 시작하고, 구매할 재료가 있는 메뉴에 대해서만 추가 재료를 짧게 안내한다. 여러 보유 재료를 조합하는 메뉴를 허용한다. 레시피, 선정 이유, JSON, 모델 정보는 읽지 않는다.
- 추천에는 관측한 재료를 활용한다. 보유 재료 ID와 추가 구매 재료명을 구분하며, 카레가루·당면처럼 YOLO 학습 클래스 밖의 재료도 구매 후보로 제안할 수 있다. 그것을 이미 보유한 재료나 새 탐지 결과로 바꾸지 않는다. 가격·매장 재고·실제 구매 가능 여부는 확인했다고 말하지 않는다.
- 최근 3일은 한국 시간 기준 오늘·어제·그저께다. 개수 제한 없이 이 기간에 먹기로 선택한 메뉴를 모두 추천에서 제외한다. 추천만 했거나 TTS로 읽은 것만으로는 기록하지 않는다.
- 같은 응답의 메뉴끼리 중복을 금지한다. `딴 메뉴 없어?`는 같은 추천 이벤트에서 이미 안내한 메뉴도 임시로 제외하고 다른 메뉴를 제안한다. 이벤트 종료 후의 새 추천에는 이전 이벤트의 단순 추천 이력을 적용하지 않는다.
- 사용자가 `그래, 달걀말이 먹자`처럼 메뉴명을 명확히 말하며 먹기로 정하면 `recent_meals.json`에 메뉴와 선택 날짜를 저장한다. 실제 섭취 확인이 아닌 식사 결정 기록이다. 선택이 모호하거나 부정 표현이면 저장하지 않는다.
- 선택 처리는 추천을 먼저 받았는지와 관계없이 허용하며, 새 촬영·YOLO·VLM 없이 진행한다. 추천 밖의 메뉴나 최근 기록에 이미 있는 메뉴라도 사용자가 명확하게 먹기로 정하면 저장한다. 추천 제외 조건을 사용자 선택의 제한으로 사용하지 않는다.
- `둘 다 먹자`는 현재 이벤트에서 가장 최근에 안내한 메뉴를 모두 선택한 것으로 처리하고 같은 날짜로 함께 저장한다. 1개만 안내했다면 그 메뉴만 저장한다. 참조할 추천이 없거나 선택이 불명확하면 저장하지 않고 `그래서 뭘 드시나요? 알려주세요!`라고 묻는다. 최근 추천은 문맥 해석용이지 선택 허용 목록이 아니다.

## 검증 가능한 구현

- 모델 출력은 검증되지 않은 입력으로 취급한다. JSON 해석, 이름 정규화, 최근 메뉴 제외, 재료 ID 검사 후 최종 문장을 코드로 만든다.
- `계란말이`/`달걀말이`처럼 알려진 동의어는 별칭 사전으로 비교한다. 미등록 동의어와 요리의 실제 성립 여부까지 완벽하게 검증한다고 주장하지 않는다.
- 유효 메뉴가 1개만 있어도 바로 추천하며 개수를 채우려고 재생성하지 않는다. 0개면 `추천할 메뉴가 없어요`라고 말한다. 최근 메뉴를 재사용하거나 없는 재료를 보유한 것처럼 꾸미지 않는다. 없는 재료가 필요한 메뉴는 구매할 재료를 명시한다.
- 하네스의 순수 규칙 검증은 GPU·카메라·마이크 없이 실행 가능하게 한다. 하네스 코드에서 실물 모듈을 무조건 import하지 않는다.
- 외부 프로그램은 환경별 실행 파일의 절대경로와 인수 목록으로 호출한다. 셸에서 가상환경을 연속 활성화하거나 음성·모델 출력을 명령으로 실행하지 않는다.
- 질문은 한 번에 하나씩 처리한다. 요청별 폴더·관리 번호·사진과 음성 이력·상세 로그 보관 기능은 만들지 않는다. 사진·음성은 고정 경로에 덮어쓰고, 실패하면 이전 파일이나 추천을 재사용하지 않는다. 식사 기록은 명확한 메뉴 선택 때만 갱신하고, 파일이 손상됐으면 기존 내용을 덮어쓰지 않는다.
- 통과한 검사, 모의 검사, 미실행 검사를 구분해서 기록한다. 검증 결과를 만들거나 추정해 채우지 않는다.

## 저장과 종료

- 재사용 코드·설정·문서는 버전 관리한다. 런타임 사진·음성·로그·캐시·생성 모델·개인 식사 기록은 버전 관리에서 제외한다.
- 테스트에서는 임시 디렉토리의 가상 식사 기록만 사용한다. 실제 기록을 덮어쓰지 않는다.
- 종료·취소·타임아웃 때 이 프로젝트가 시작한 작업만 정리한다. 다른 학습·카메라·사용자 프로세스를 종료하지 않는다.
- 기능을 변경하면 관련 명세와 체크리스트도 같은 작업에서 갱신한다.
