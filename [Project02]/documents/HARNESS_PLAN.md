# 하네스 설계 — v0.1

상태: **설계만 작성. 아래 테스트·가상 입력 파일·실행 명령은 아직 구현되지 않았다.**

하네스는 정해진 입력을 넣고 기대 결과와 비교하는 검증 틀이다. 실제 인식 모델의 정확도와 장치 동작까지 모의 테스트로 증명하지 않는다.

## 1. 세 단계 검증

| 단계 | 입력과 도구 | 검증 대상 | 증명하지 못하는 것 |
| --- | --- | --- | --- |
| A. 순수 규칙 | 가상 STT 텍스트·재료 JSON·식사 파일·모델 응답 | 최근 3일 기록, 정규화, 출력 형식, 재시도·상태·오류 | 카메라·STT·VLM 정확도 |
| B. 저장 자료 + 실제 모델 | 정답을 적은 사진·녹음과 실제 어댑터 | 실제 모델 호출, 재료 인식, 구조화 응답, 시간 | 실제 냉장고·실시간 장치 안정성 |
| C. Jetson 현장 | 카메라·마이크·스피커·TensorRT 모델 | 전체 연결, 메모리, 지연, 재촬영·반복 요청 | 학습 데이터 밖 모든 환경의 일반화 |

현재 재료가 없어도 A는 가능하다. B에서는 개발용 사진·검증용 사진을 사용한다. 학습의 최종 테스트 190장은 개발·프롬프트 조정용으로 반복 사용하지 않고 마지막 평가에 남긴다.

## 2. 하네스 입력·출력

- 케이스마다 오늘 날짜, 질문·선택 텍스트, 입력 사진, YOLO 응답, VLM 응답, 식사 기록, 추천 응답 1~2개, 어댑터 장애 여부를 고정한다.
- 가상 어댑터는 호출 내역과 순서를 기록하고 정해진 결과를 반환한다. CPU 시간·임의 난수·실제 파일 시각에 의존하지 않는다.
- 테스트용 임시 디렉토리에 고정 파일과 가상 식사 기록을 둔다. 추천만 할 때는 메뉴를 추가하지 않고, 명확한 선택 때만 식사 기록이 갱신돼야 한다.
- 출력은 최종 상태, 추천 메뉴, 사용자 문장, 거절 사유, 단계 호출 횟수·순서다.
- 실제 모델 테스트는 정확한 메뉴명 문자열보다 자료형·최근 메뉴 제외·출력 템플릿을 검사한다. 추천의 타당성은 별도 사람 평가 항목으로 남긴다.

## 4. 실제 모델·장치 평가 기록

| 항목 | 기록할 내용 |
| --- | --- |
| 재료 인식 | 정답 재료, YOLO 결과, VLM 최종 목록, 누락·오인식 |
| 메뉴 타당성 | 최근 메뉴 중복, 보유 재료 활용, 추가 재료 누락·과도한 구매 제안, 메뉴와 필요한 추가 재료만 안내했는지 |
| 응답 대기 | 사용 중 멈추거나 기다리기 불편한지 확인. 상세 시간은 필요할 때만 측정 |
| 메모리 | 모델 상주·로딩 때의 Jetson RAM/GPU 공유 메모리, 실패 여부 |
| 반복성 | 같은 재료로 최근 기록을 바꾼 요청, 다른 재료 배치, 재시작 후 기록 유지 |

질문별 시간 자동 측정·저장은 요구하지 않는다. 속도 때문에 문제가 생기면 필요한 부분만 확인한다. 실제로 확인하지 않은 응답 속도를 통과했다고 기록하지 않는다.

## 5. 구현 후 실행 방식 제안

`tests/`에 카메라 없는 규칙 테스트와 가상 어댑터 기반 파이프라인 테스트를 두고 `python -m unittest discover`로 실행 가능한 구조를 우선 제안한다. 실제 모델·장치 검사는 별도 명시적 실행으로 분리해 기본 테스트가 GPU나 카메라를 열지 않게 한다. 명령·경로는 실제 구현 뒤 README에 확정해서 적는다.
