## 테스트에서 확인한 동작

- 최근 3일의 9개 기록을 모두 사용하고 이전 날짜 제외. 별칭·같은 응답 중복 정리.

- 모호·부정·질문 형태와 `카레 아니면 잡채 먹자` 같은 미정 선택은 저장하지 않음.
- 재료 조회는 중복 없이 종류만 안내, 식사 파일에 접근하지 않고 추천 문맥 유지.
- 신뢰도 경계 분류, 여러 애매한 후보에 확인 호출 한 번, 없는 번호·중복 번호·미지원 재료 거절. VLM 실패 때 확실한 재료 보존.
- 생성한 색상 배열로 두 bbox가 한 콜라주에 포함되는지 확인. 실제 식재료 사진 인식 검사는 아님.

- Whisper 호출 인수와 Piper 실패 시 이전 음성 미재생 검사. 실제 Whisper·Piper 실행은 아님.
- 작은 Python 응답 프로세스로 Gemma 통신의 재사용·종료·타임아웃 정리 확인. 실제 Gemma 추론 검사는 아님.

## 최종 코드 리뷰 후 회귀 검사

다섯 가지 기존 의도·메뉴명 오류를 재현한 뒤 수정했다. 추천·재료 조회 충돌, 추천 금지 표현, 복합 문장의 잘못된 모두 선택, `주먹밥`·`먹물파스타` 거절, `마시멜로` 잘림을 검사한다. `그래놀라` 보존, 한글 받침에 맞는 일부 조사 처리, 100자 초과 입력의 미저장도 확인했다.

수정 중 서브에이전트가 발견한 `대신에`, `싫어` 복합 선택 회귀도 실패 테스트로 재현하고 수정했다. 최종적으로 실행 환경 `.venv-ingredients`에서 테스트 **51개 통과, 스킵 0개**를 확인했고, 서브에이전트도 독립 실행으로 같은 결과를 확인했다. 테스트 파일은 계속 Git에서 제외한다.

음식 선택은 고정 음식 목록으로 제한하지 않는다. 다만 모르는 음식 이름 끝의 `로`와 조사를 일반적으로 구별할 수는 없어 원래 이름을 보존하는 쪽을 택했다. 등록된 패턴 밖의 자연어·별칭 처리를 완전히 보장하지 않는다.

- 녹음 그룹 종료 후 PulseAudio 스피커가 SUSPENDED 상태에 남아 aplay가 대기하는 현상을 확인했다. `pactl suspend-sink @DEFAULT_SINK@ 0`으로 복구했고 녹음 종료 시 이 복구를 수행하도록 수정했다. 수정 후 추천 안내 재생을 마치고 `말씀을 시작해 주세요`로 복귀하는 실제 동작을 확인했다.
- 실제 `메뉴 추천해줘` 발화에서 새 촬영·YOLO·후보 VLM·Gemma 메뉴 생성·코드 검증·TTS를 거쳐 `추천 메뉴는 감자전입니다. 감자전의 추가 재료는 밀가루, 소금입니다.` 응답과 자동 듣기 복귀를 확인했다. 이 요청의 관측 재료는 양파·감자·계란이며 당근은 누락됐다.
- 변경 후 로컬 테스트 73개 통과. 초기 모델 로딩을 포함한 첫 요청은 약 1분 이상 걸렸으며, 모든 요청의 지연이나 인식 정확도를 검증한 것은 아니다. 대안 요청 `다른 메뉴 추천해줘`에서 감자전을 제외한 계란볶음밥과 추가 재료 밥을 안내했고, 사용자 청취도 확인했다. `오늘은 계란 볶음밥 먹자` 발화 후 `recent_meals.json`에 계란볶음밥과 2026-11-08 저장을 확인했다. 구매 재료 조회의 현장 확인은 별도다.

현장 STT는 `딴 메뉴 없어? → 단면이 없어?`, 주변 소음의 `(끝)`·의성어 인식 등 오류가 있었다. 메뉴명이 불명확한 경우 저장하지 않았으며, 또박또박 긴 표현으로 재발화한 선택은 성공했다. 소음 환경의 VAD 기준값·마이크 위치·Whisper 인식률은 추가 조정이 필요하다.

구매 재료 현장 첫 시도에서는 `카레가 먹고 싶어…`를 STT가 `칼아가 먹고 싶어…`로 인식했고, Gemma가 `칼아 면`을 제안했다. 이는 구매 질문 분기·촬영·차집합·음성 출력이 실행됐다는 증거일 뿐, 요청한 카레의 올바른 구매 안내 성공은 아니다. 같은 촬영의 관측에는 사진에 없는 소시지도 포함돼 재료 오인식이 확인됐다.

구매 재료 재시도에서는 음식명이 `카리`로 인식됐고 감자만 관측한 뒤 닭고기·양파·토마토·향신료 등 긴 구매 목록을 안내했다. 카레에 대한 사용자 의도와 현재 재료를 정확히 반영한 안내로 검증된 것은 아니다. 재료 조회·일반 추천·이벤트 내 대안 추천·선택 파일 저장과 재생 후 듣기 복귀는 확인했지만, STT와 사진 인식의 안정성은 남은 현장 과제다.

## FP32 전환과 실제 앱 검사

2026-11-08 사용자 결정에 따라 앱의 기본 엔진을 `ingredients_fp32.engine`으로 변경했다. 원본 FP32 계산 데이터에 같은 학습 모델의 36종 클래스 이름 메타데이터만 추가했다. 실시간 미리보기에서 클래스 이름·confidence 표시와 추론 실행을 확인했다. INT8과의 비교는 정량 정확도 평가가 아니다.

첫 앱 검사에서는 촬영 사진의 색상이 심하게 왜곡됐고 메뉴 응답도 검증에 실패했다. 별도 카메라 검사에서 90프레임 후 정상 색상 영상을 확인하여 앱 촬영 대기를 15프레임에서 90프레임(30 FPS 기준 약 3초)으로 늘렸다.

다음 실제 발화 `메뉴 추천해주세요`에서 FP32 로딩 → YOLO → 후보 VLM → Gemma JSON → 코드 검증 → Piper·aplay → 다시 듣기 복귀를 확인했다. 응답은 `추천 메뉴는 감자채 볶음입니다. 감자채 볶음의 추가 재료는 소금, 식용유입니다.`였다. 관측 재료에는 감자·양파·토마토·당근이 포함됐으며 사진의 계란 오인식 등 정확도 문제는 해결됐다고 주장하지 않는다. 기존 계란볶음밥 식사 기록도 제외 목록에 전달됐다.

기본 FP32 경로를 사용하는 실행 루프 검사와 기존 규칙·어댑터 검사 총 73개가 로컬에서 통과했다. 정상 시연 후 프로젝트 폴더의 `ingredients_int8.engine`을 삭제하고 테스트 프로세스를 종료했다. 외부 학습·변환 폴더와 강의의 기본 YOLO 모델은 삭제하지 않았다. 엔진은 Git에서 제외한다.

## 강의 폴더 기준 경로와 활성 환경 사용

`--resource-root`, `--gemma-python` 실행 옵션을 제거했다. `[Project02]`의 상위 폴더에서 강의 모델·실행 파일을 찾고, Gemma는 메인 프로그램과 같은 Python을 사용한다. Piper는 기존 강의 방식의 `.piper_venv`를 유지한다. 실행 루프 모의 검사에서 Gemma·자원 확인·TTS에 같은 상위 폴더를 전달하는지 확인했고, 기존 검사 포함 73개가 통과했다. CLI 도움말과 문법 검사도 확인했다. 이 경로 변경 후 전체 음성 시연을 다시 실행한 것은 아니다.
