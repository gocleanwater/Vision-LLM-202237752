# 구현·검증 체크리스트 — v0.1

상태: 구현 전. 세부 구현 계획은 설계 검토 후 확정한다. 체크 표시는 실제 파일·실행 결과가 있을 때만 한다.

## 1. 계약과 순수 규칙

- [ ] 연속 음성 감지의 시작·끝 이벤트를 주입 가능하게 두고, 실제 감지 도구와 무음·최대 발화 설정은 마이크 시험 후 정한다.
- [ ] `contracts.py`에 데이터 계약의 입력·출력 타입과 오류 결과를 정의한다.
- [ ] `policy.py`에 음식·재료 별칭 정규화, 메뉴 JSON 검증, 최근 메뉴·중복 제외, 고정 문장 생성을 구현한다.
- [ ] 보유 재료 ID와 추가 구매 재료명을 구분하고, 여러 재료 조합을 허용한다. 구매할 재료가 있을 때만 메뉴별 추가 안내를 붙인다.
- [ ] 탐지 하한과 바로 사용할 confidence 기준으로 후보를 나누고, 확실한 재료와 VLM 확인 결과를 합치는 규칙을 구현한다. 실제 기준값은 사진 시험 후 정한다.
- [ ] `history.py`에 한국 시간의 오늘·어제·그저께 기록 읽기와, 선택 메뉴·날짜 저장을 구현한다. 개수 제한은 두지 않는다.
- [ ] 추천 여부와 관계없이 메뉴명을 명확히 말한 긍정 선택과, 일반 질문·부정·모호한 발화를 구분한다. 메뉴 선택 때 카메라·YOLO·VLM을 다시 실행하지 않는다.
- [ ] H03~11, H17의 실패 사례부터 검사하고 각 규칙이 실제로 통과하는지 기록한다.

## 2. 장치 없는 파이프라인 하네스

- [ ] 사진·YOLO·VLM·STT·TTS를 주입 가능한 어댑터 경계로 둔다.
- [ ] `pipeline.py`에 순차 단계 실행·최대 1회 보완·중복 억제를 구현한다. 요청별 폴더와 이력 저장은 만들지 않는다.
- [ ] 가상 결과와 임시 식사 기록으로 H01~47을 재현한다. 애매한 후보가 없으면 이미지 호출 0회, 여러 개여도 1회인지 확인한다.
- [ ] 유효한 1개를 그대로 안내하고, 같은 이벤트의 다른 메뉴 요청에는 이미 안내한 메뉴 전체를 제외한다. 후보 없음 문장과 이벤트 종료 후 임시 목록 삭제도 검사한다.
- [ ] 재료 조회는 새 사진에서 종류만 중복 없이 음성 안내한다. 개수·메뉴 추천·구매 제안·식사 기록 접근이 없고 최근 추천 문맥은 유지하는지 확인한다.
- [ ] `둘 다 먹자`는 현재 이벤트의 마지막 안내 1~2개를 모두 저장하고, 참조가 없거나 선택이 불명확하면 정해진 문장으로 되묻는지 확인한다.
- [ ] 고정 사진·음성 파일을 덮어쓰고, 단계 실패 시 이전 성공 파일이나 결과를 재사용하지 않는지 확인한다.
- [ ] 기본 테스트가 카메라·마이크·GPU·실제 기록 파일에 접근하지 않는지 확인한다.

## 3. 실제 모델을 저장 자료로 연결

- [ ] 루트 학습에서 생성된 식재료 `best.pt`의 클래스 목록·해시를 확인한다. Project02에서 다시 학습하지 않는다.
- [ ] 검증용 사진으로 YOLO와 Gemma VLM의 재료 인식을 따로 기록한다.
- [ ] 실제 Gemma에 이미지가 전달되는지 확인한다. 고정 응답으로 대체한 결과를 실제 VLM 검증으로 쓰지 않는다.
- [ ] 애매한 후보 영역들을 하나의 이미지에 모아 VLM에 전달하고, 확인 불가·실패 때 해당 후보만 제외하는지 확인한다.
- [ ] 자유 생성 메뉴를 검증한 뒤에만 고정 출력 문장을 만드는지 확인한다.
- [ ] 자료를 보고 프롬프트를 조정한 기록과 최종 평가 자료를 분리한다.

## 4. Jetson 연결과 최적화

- [ ] 모델·실행 환경·카메라·마이크·스피커 경로를 실제 Jetson에서 확인한다.
- [ ] 식재료 사진으로 calibration한 INT8 엔진을 해당 Jetson에서 생성하고 `.pt` 결과와 비교한다. FP32·FP16 엔진 생성은 필수가 아니다.
- [ ] 완성된 엔진을 Project02 루트의 `ingredients_int8.engine`에 배치하고 클래스·해시·실제 로딩을 확인한다. 측정용 raw 엔진을 배치하지 않는다.
- [ ] STT → 카메라 → YOLO → 애매한 후보가 있을 때만 VLM 확인 → 기록 → Gemma 메뉴 추천 → TTS를 실제 연결한다.
- [ ] 환경별 실행 파일 호출, 타임아웃, 종료 시 자원 정리를 검증한다.
- [ ] 모델을 함께 사용할 때 메모리 부족이나 불편한 대기가 없는지 확인하고, 필요하면 상주·재로딩 방식을 조정한다. 상세 시간 자동 수집은 만들지 않는다.
- [ ] 키·버튼 없는 연속 감지, 발화 종료 판정, 처리·TTS 중 입력 폐기, 자동 감지 재개와 실제 에코·잔향에 의한 재인식 여부를 확인한다.

## 5. 시연과 제출 기록

- [ ] 재료별 인식 성능을 보고 시연 재료를 정한다. 약한 클래스가 잘 된다고 가정하지 않는다.
- [ ] 현재 재료가 같아도 최근 식사 기록을 바꾸면 제외 결과가 달라짐을 시연한다.
- [ ] 추천만 하면 메뉴를 추가하지 않고, 명확한 선택 뒤에만 파일을 갱신하는지 확인한다. 추천 밖 선택·추천 전 선택·저장 실패·재시작 후 읽기도 검사한다.
- [ ] `추천 메뉴는 A, B입니다.`와 필요한 추가 재료만 짧게 출력하는지 확인한다. 레시피·선정 이유·매장 재고·가격 정보는 출력하지 않는다.
- [ ] 같은 응답·최근 3일 선택 메뉴·같은 이벤트의 앞선 안내 메뉴는 중복을 금지하고, 종료된 이벤트에서 추천만 했던 음식은 새 이벤트에서 허용하는지 확인한다.
- [ ] 식사 기록은 실제 섭취가 아닌 사용자의 메뉴 선택이라는 점과 실제 구현 기능·미검증 한계를 구분해 기록한다.
- [ ] 코드·문서만 게시하고 개인 식사·음성·사진·로그·가상환경은 게시 대상에서 제외한다.

## 진행 중인 별도 작업

Mac의 루트 `train_yolo_ingredients.py` 30 epoch 학습은 완료됐으며, 그 최적 `best.pt`의 Jetson INT8 변환은 별도 작업이다. 이 문서에는 변환 완료나 Project02 루트 배치를 완료로 표시하지 않는다. 실제 파일·로그를 확인한 뒤 갱신한다.
