# 확정 사항과 남은 결정 — v0.1

기준일: 2026-11-07. 사용자 결정과 구현 제안·실측 대기를 구분한다.

## 사용자와 확정한 사항

| 항목 | 결정 |
| --- | --- |
| 목적 | 매일 가족 식사 메뉴를 고민하시는 어머니의 부담 줄이기 |
| 장면 | 책상 위 식재료를 냉장고 안으로 가정 |
| 이벤트 | 사용자가 먼저 음성으로 메뉴를 질문하면 추천 시작 |
| 재료 조회 | `냉장고에 식재료 뭐뭐 있어?`는 현재 사진을 분석해 종류만 음성 안내. 개수·중복 이름·메뉴 추천·구매 제안·식사 기록 접근 없음 |
| 핵심 기술 | YOLO 식재료 탐지 + Gemma VLM + STT + TTS |
| 음성 입력 | 키·버튼 없이 연속 음성 감지. 발화 종료 후 STT 처리, 응답 뒤 자동 대기 복귀 |
| 추천 범위 | 여러 보유 재료를 조합하는 메뉴와 추가 재료를 준비하는 메뉴 모두 허용. 레시피 제외 |
| 최근 식사 기준 | 한국 시간 기준 오늘·어제·그저께에 먹기로 선택한 메뉴 전부. 개수 제한과 과거 72시간 기준은 사용하지 않음 |
| 선택 시 갱신 | `그래, ○○ 먹자`처럼 메뉴명과 먹기로 한 의사를 명확히 말하면 추천 밖 메뉴나 추천 전 선택도 허용하고 `recent_meals.json`에 메뉴와 선택 날짜 저장. 실제 섭취 확인은 아님 |
| 둘 다 선택·되묻기 | `둘 다 먹자`는 현재 이벤트의 마지막 추천 1~2개 모두 저장. 불명확하면 `그래서 뭘 드시나요? 알려주세요!`라고 물음 |
| 재료 확인 대화 | 별도 확인 없이 바로 추천 |
| VLM 활용 조건 | YOLO에서 confidence가 높은 재료는 바로 사용하고, 애매한 후보만 한 이미지로 모아 VLM에서 한 번 확인. 후보가 없으면 이미지 분석 생략 |
| 추천 방식 | Gemma 자유 생성 후 코드로 형식·최근 메뉴 검사 |
| 성공 출력 | 메뉴는 최대 2개. 1개도 그대로 추천하며 필요한 추가 구매 재료를 짧게 안내 |
| 다른 메뉴 요청 | 같은 이벤트에서 이미 안내한 메뉴를 제외해 다시 추천. 후보가 없으면 `추천할 메뉴가 없어요` 안내 |
| 추천 임시 저장 | 한 추천 이벤트 동안만 메뉴 이름을 메모리에 보관하고 종료 때 비움. 선택한 메뉴와 날짜만 식사 파일에 저장 |
| 메뉴 중복 제외 범위 | 같은 응답 내 중복과 최근 3일 선택 메뉴 제외. 같은 이벤트의 대안 요청에는 그동안 안내한 메뉴도 임시 제외. 이벤트 종료 후 임시 목록 삭제 |
| 개발·실행 | Mac에서 학습, Jetson에서 최적화·최종 실행 |
| YOLO 모델 위치 | Project02 루트의 `ingredients_int8.engine`에 최종 모델이 있다고 가정. 실제 배치는 별도 확인 |
| 최적화 대상 | 학습한 `best.pt`를 calibration 후 TensorRT INT8로 변환. FP32·FP16 생성은 필수 아님 |
| 현재 산출물 | 설계 문서와 네 실행 파일 1차 구현, 로컬 테스트. 실제 Jetson 전체 연결 시험은 남음 |
| 임시 파일 | 질문별 폴더·관리 번호·사진과 음성 이력·상세 로그 보관 없이 고정 파일을 덮어씀. 식사 결정 파일은 선택 때 갱신하고 재시작 후에도 유지 |

## 구현자가 정할 수 있는 초안

| 항목 | 현재 제안 | 확인 방법 |
| --- | --- | --- |
| 결과 검증 실패 | 잘못된 형식·금지 후보는 최대 1회 수정 요청. 유효한 1개를 채우기 위한 재생성은 하지 않음 | 하네스의 출력·오류 사례 |
| 모델 재생성 | 최대 1회, 유효 항목 유지 | 하네스 H06~09 |
| 처리 중 요청 | 처리·TTS 중 음성은 실행하거나 쌓지 않고, 끝나면 남은 입력을 버린 뒤 다시 듣기 | H14, H47과 실제 음성 시험 |
| 후보 확인 실패 | VLM이 확인하지 못한 후보는 제외하고 확실한 YOLO 재료는 유지. 최종 재료가 없으면 인식 불가 안내 | H12, H22, H23 |
| 상시 재료 | 기본 빈 목록, 자동으로 소금·기름·쌀 가정하지 않음 | 필요하면 명시적 설정 추가 |
| 추가 구매 상한 | 메뉴당 최대 2종을 초안으로 제안. 사용자 확정값은 아님 | 구현 전 실제 추천 예시를 보고 결정 |
| 검증 도구 | 표준 `unittest` 우선, 순수 규칙과 장치 검사 분리 | 구현 후 실제 실행 명령 확정 |

## 구현 전 또는 현장 시험에서 정할 항목

| 항목 | 아직 모르는 것 | 결정 시점 |
| --- | --- | --- |
| 음성 감지 설정 | 음성 시작 기준·종료 무음 길이·최대 발화 길이·사용할 감지 도구 | 실제 마이크의 말소리·무음·주변 소음으로 확인해 결정 |
| 시연 재료 | 36종 중 실제로 잘 인식되는 재료와 배치 | 학습 완료와 저장 사진·실물 평가 후 |
| 음식 별칭 | 최근 식사와 시연 메뉴의 실제 표현 목록 | 가상 기록·추천 사례를 만들 때 보완 |
| 장치 경로 | 카메라 파이프라인, 녹음·재생 장치 번호 | Jetson 연결 때 확인 |
| 모델 환경 | Gemma VLM의 실제 실행 환경과 대응 mmproj, 정해진 루트 경로에 INT8 엔진이 실제 배치됐는지 | 모델 어댑터 작성 전 확인 |
| 제한 시간·임계값 | 단계별 타임아웃, `DETECT_CONF`와 `ACCEPT_CONF` 두 confidence 기준 | 실제 사진으로 기준 설정. `0 <= DETECT_CONF < ACCEPT_CONF <= 1`. 처리 속도는 필요할 때 확인 |
| 모델 상주 | YOLO·Gemma 동시 상주 가능 여부, 로딩 비용 | Jetson 메모리·단계 지연 측정 후 |
| 초기 시연 기록 | `recent_meals.json`에 넣을 가상 메뉴·날짜. 첫 실행 때 파일이 없으면 빈 기록 생성 | 사용자 결정에 따라 발표자료를 만들 때 준비. 지금은 생성하지 않음 |

## 알려진 한계

- 원본 데이터 안내는 1,904장, 받은 공개 저장소 사본은 1,901장이다. GitHub 전송에서 빠진 것은 아니며 3장 차이의 이유는 미확인이다.
- 데이터의 클래스별 수가 불균형하다. 학습용 전체를 사용해도 모든 재료가 잘 인식된다는 뜻은 아니다.
- 자유 생성 메뉴의 모든 동의어·필수 재료 누락을 코드로 완전 판정하지 못한다. 해당 한계를 사용자 결정과 구분해서 설명한다.
- 카메라에 안 보이는 재료, 실제 섭취, 냉장고 전체 재고, 신선도는 자동으로 알 수 없다.
- YOLO가 아예 탐지하지 못한 재료는 조건부 VLM 확인의 대상이 되지 않는다. VLM의 확인도 정답을 보장하지 않는다.
- 사진·모델·오디오를 실제로 연결하기 전에는 전체 시스템이 동작하거나 빠르다고 주장하지 않는다.
