# Project02 구현 계획

기준: FEATURE_SPEC.md, DATA_CONTRACTS.md와 사용자의 노트북 재사용 요청.

현재 프로젝트 폴더에서 `codex/project02-implementation` 브랜치로 작업한다. 테스트는 로컬 `tests/`에 두고 제출용 Git 파일에서 제외한다. 새로운 가상 식사 데이터셋은 만들지 않는다.

1. `main.py`: 의도 분기, 날짜별 식사 기록, 메뉴 검증·출력, 이벤트 임시 목록. 먼저 임시 파일과 가상 모델 응답으로 실패 테스트를 작성하고 구현 후 통과를 확인한다.
2. `vision.py`: `int8_yolo.py`의 YOLO 엔진·GStreamer 입력·predict 코드를 재사용한다. 한 질문에 한 사진만 분석하고 애매한 bbox만 잘라 한 이미지로 확인한다. VLM 실패 시 확실한 재료는 유지한다.
3. `gemma.py`: 06 노트북의 Llama·Gemma4ChatHandler·base64 이미지 입력을 재사용한다. 환경을 지정할 수 있는 별도 Python 프로세스에서 모델을 재사용하고 호출 제한 시간을 둔다.
4. `speech.py`: 06 노트북의 arecord·whisper-cli·Piper·aplay 명령을 재사용한다. 녹음만 연속 PCM 입력의 음성 구간 감지로 변경한다. 녹음 프로세스는 매 발화 뒤 종료하므로 처리·TTS 중 입력이 쌓이지 않는다.
5. 전체 로컬 테스트, 문법 검사, CLI 도움말, Git 제외 규칙 확인 후 문서·실행 안내를 실제 구조로 갱신한다. 실제 장치와 모델 시험은 접속·장치가 가능한 범위에서 수행하며 모의 검증과 구분한다.

시작값은 실물 확정값이 아니다: YOLO 탐지 0.15·즉시 수용 0.65, 음성 RMS 500·종료 무음 0.8초·최대 발화 15초. 추가 구매 종류 수는 아직 사용자 확정값이 없으므로 임의의 2종 상한으로 거절하지 않는다.

## 지정 메뉴 구매 재료 조회 추가

사용자가 지정한 메뉴의 전체 필요 재료를 기존 Gemma 텍스트 호출로 제안받고, 새 관측 재료를 코드에서 제외한다. main.py에 메뉴 추출·재료 키·차집합 검증과 별도 분기를 추가하고 gemma.py에 전체 재료 JSON 요청을 추가한다. 메뉴가 없으면 먼저 되묻고, 조회는 식사 기록과 추천 이벤트를 건드리지 않는다. 실패·별칭·모두 보유·기존 기능 유지 테스트를 로컬에 추가한다. 라이브러리·파일 구조·PPT 장수는 늘리지 않는다.
