상태: 통합 게임·한글 화면·저장 영상·선택형 추적 코드 추가 · 2026-10-23. `2026.10.18/` 실습처럼 일반 클래스·함수·변수 중심으로 구성한다. 순수 게임 로직과 별도로 MediaPipe 손 결과 변환, LAB 색별 공 후보·오버레이, 최신 카메라 프레임과 순수 게임 연결, 한글 정보 띠, 저장 영상 입력과 기본 OFF 추적을 구현했다. 실제 OpenCV·MediaPipe 실행과 장비 시험은 Jetson에서 확인해야 한다. 구조는 [HARNESS_DESIGN.md](HARNESS_DESIGN.md), 승인된 단계 순서는 [HARNESS_IMPLEMENTATION_PLAN.md](HARNESS_IMPLEMENTATION_PLAN.md), 실제 검증 결과는 [IMPLEMENTATION_CHECKLIST.md](IMPLEMENTATION_CHECKLIST.md)를 따른다.

## 한 문장 목표

Jetson에 연결한 카메라의 실시간 영상에서 **각 손과 색깔 공의 관계**를 판정하여, 화면이 요구한 색의 공을 왼손과 오른손에 올바르게 보여주기까지 걸린 시간과 성공 횟수를 기록하는 게임을 만든다.

## 사용자에게 보이는 한 판

1. 카메라 화면에 출발 영역과 제시 영역이 표시된다.
2. 공과 제시 영역이 준비되면 화면이 `왼손: 초록 / 오른손: 빨강`처럼 무작위 문제를 제시한다.
3. 사용자는 종이컵 위의 공을 골라 카메라 중앙의 제시 영역에서 양손에 해당 색 공을 하나씩 보여준다. 손바닥을 살짝 오므려도 되며 손가락을 모두 펼 필요는 없다. 공과 양손의 위치가 영상에 보여 어느 손의 공인지 구분되어야 한다. 영상 판정은 손 영역과 공의 관계를 확인하며 **물리적 접촉 자체를 증명하지는 못한다.**
4. 화면에는 손 레이블, 공의 실제 검출 위치, 손에 가려진 직후의 짧은 예측 위치, 손별 정오 피드백, 경과 시간이 나온다. 오래 가려지거나 화면 밖으로 나간 공은 위치를 안다고 표시하지 않는다.
5. 두 손에 제시된 공의 색과 공이 올라온 손이 확인되고, **문제에 선택되지 않은 세 번째 공이 출발 영역에 실제로 보이면** 1점을 얻고 반응 시간을 기록한다. 완성된 제시 자세에서 색 오답이나 남은 공의 출발 영역 이탈이 안정적으로 확인되거나 시간이 초과되면 기회가 1개 줄어든다. 기회 3개가 모두 소진되면 한 판이 끝난다.

판정 결과는 첫 구현값으로 1.5초 보여준다. 기회가 남으면 `다음 라운드를 위해 공을 제자리에 두고 손은 손 대기 영역 안에서 대기하세요.`라고 안내하고, 공 3개와 양손이 준비 조건을 충족할 때까지 기다린다. 준비가 0.5초 유지되면 3초 카운트다운을 시작하고, 그 뒤 새 문제를 제시한다. 오답·시간 초과 뒤에도 동일하다. 카메라 장애로 문제가 무효가 되면 라운드 번호와 점수·기회는 유지하고, 복구 뒤 GAME_RULES 3절의 같은 기준으로 다시 추첨한다.

## 기본 범위와 의도적 제한

공의 준비 위치는 출발 영역 전체를 기준으로 확인한다. 세 색 공의 중심이 그 영역 안에 각각 유일하게 실제 검출되면 충분하며, 원래 컵 위치나 컵 위 여부는 검사하지 않는다.

| 구분 | 첫 완성 목표 |
| --- | --- |
| 입력 | 위에서 아래를 촬영하는 고정 USB 카메라 1대, 사람 1명, 두 손. Jetson Orin Nano로 추정하나 모델 미확인 |
| 공 | 빨강·초록·파랑 탁구공 각 1개. 빨강·파랑은 물감으로 준비할 예정이고 초록은 강사에게 요청할 예정 |
| 문제 | 서로 다른 두 색을 왼손·오른손에 한 개씩 지정 |
| 판정 | 손가락 모양과 관계없이, 지정 색 공의 실제 검출 중심이 제시 영역과 각 손의 손바닥 상자에 하나씩 있고, **남은 한 색 공도 출발 영역에 실제로 보이는** 장면을 기준으로 판정 |
| 게임 | 기회 3개로 시작. 성공 +1점, 안정적으로 확인된 오답 또는 시간 초과 시 기회 -1. 점수·기회·상태는 화면 하단에 표시 |
| 보류 | 같은 색 공 2개 이상, 2인 플레이, 추가 손동작 명령, 온라인 순위표 |

기본 범위의 수치와 색상은 하드코딩된 사실이 아니라 **초기 설계값**이다. 카메라·공 실물 시험을 통해 바꿀 수 있으며 승인한 변경은 `GAME_RULES.md`와 사용하는 파일 상단 변수에 함께 반영한다.

## 촬영 배치와 준비물

카메라는 탁자 위에서 아래로 고정한다. 원본 640×480 영상에서는 왼쪽에 뒤집은 종이컵 3개와 공(출발 영역), 가운데에 두 손을 제시하는 빈 공간(제시 영역), 오른쪽에 손 대기 공간을 둔다. 카메라 프레임을 읽은 직후 `cv2.ROTATE_90_CLOCKWISE`로 회전하면 영상은 480×640의 세로형이 되고, 세 영역은 화면 위→중앙→아래 순서로 보인다. 공·손 인식과 영역 판정은 모두 회전된 영상의 좌표로 수행한다. 정보 띠를 위아래에 더하면 최종 창 높이는 640픽셀보다 커진다. 세 구역의 경계와 실제 좌표는 현장에서 보정한다.

사용자 계획은 **같은 높이의 신발 상자 2개**를 세우고 각각 안쪽 바닥에 500 mL 생수병을 넣은 뒤, 위에 **나무젓가락 2개를 가로로 고정**해 작은 USB 카메라의 렌즈가 아래를 향하게 두는 방식이다. 아직 조립·안정성 시험이 완료됐다고 확인되지 않았다. 젓가락 양 끝과 카메라 본체를 각각 상자에 단단히 고정하고, 렌즈 아래 시야를 가리지 않으며, USB 선이 카메라를 잡아당기지 않게 상자 쪽에 여유 있게 묶는다. 카메라가 가볍더라도 상자 기울어짐·가로대 처짐·낙하 위험은 별도로 확인한다. Jetson은 거치대 오른쪽의 단단하고 평평한 책상 면에 두고 냉각부 주변 공간과 전원선 여유를 확보한다. USB 선 길이는 실제 배치에서 확인한다.

공은 색마다 하나씩 충분히 넓고 균일하게 칠하되, 손·컵·배경과 잘 구별되는지 촬영 화면에서 확인한다. 종이컵은 굴러가지 않게 고정하고 손 제시 영역과 충분히 떨어뜨려 오검출을 줄인다.

## 화면 출력 방식

`2026.10.18/mp_hand.py`는 손 랜드마크를 카메라 프레임에 그린 뒤 `cv2.imshow()` 창 하나에 표시한다. 프로젝트에서는 같은 흐름을 확장한다. 매 프레임을 시계방향 90° 회전하고 그 영상에 손·공·세 영역을 그린다. 영상과 **같은 너비**의 위쪽 문제·시간 띠와 아래쪽 점수·기회·상태 띠를 따로 만든다. 띠의 한글은 Pillow와 프로젝트에 포함한 Noto Sans KR 폰트로 그린다. 세 이미지를 세로로 합친 **한 장의 화면**을 `cv2.imshow()`에 넘긴다. 창을 세 개 띄우는 방식은 아니다. 영상 크기는 첫 시험 설정에서 480×640이고, 최종 창 높이는 두 띠의 높이만큼 더 커진다.

각 손의 손바닥 상자를 가는 청록 점선으로 표시한다. 현재 기준과 다른 이전 배치 목업은 본문에서 제외했다. Jetson에서 폰트·창 크기·표시 속도와 상자 정확도는 아직 검증되지 않았다.

## 구현 순서

손 인식과 카메라 반복문의 기준은 **`2026.10.18/mp_hand.py`**다. 모델 준비·카메라 읽기·RGB 변환·손 검출·랜드마크 표시·출력·종료 정리를 최대한 유지하고 게임에 필요한 동작만 덧붙인다. 손가락 각도·펼친 개수는 계산하지 않는다. 원본의 `finger_tips`는 표시용이다. 좌우 보정과 카메라 장애 처리는 기존 GAME_RULES를 따른다.

아래는 전체 게임의 후속 계획이다. 단계별 실행 순서는 HARNESS_IMPLEMENTATION_PLAN의 게임 구현 후속 계획을 따른다. `game.py`의 한 프레임 판정부터 입력 장애 복구까지 구현했고(5단계), `vision.py`와 `main.py`에는 손·공 관측·설정값 좌우 매핑·게임 연결·한글 화면·저장 영상·선택형 추적 코드를 추가했다. 실물 검증 전이므로 추적은 OFF다. Mac에서는 순수 계산만 확인했으며 실제 비전·카메라·GUI 검증은 Jetson에서 수행한다.

1. **카메라 없이 시작:** 게임 상태·시간·점수 로직이 프레임 자체가 아닌 시각과 구조화된 관측 결과를 입력받도록 만든다. 가짜 관측 시퀀스로 정답·오답·시간 초과·입력 장애를 검증한다. 카메라 입력과 저장 영상 입력은 같은 인터페이스로 교체 가능하게 설계한다. 현재 저장소의 수업 이미지는 이 게임의 실제 인식 성능 검증 자료가 아니다.
2. 사용자 보고에 따르면 Jetson에는 `src/models/MediaPipe/hand_landmarker.task`가 반드시 있다. `[Project01]/`에서 실행해 기존 실습과 같은 상대 경로 문자열을 MediaPipe에 바로 전달하고, Jetson에서 모델 로딩·추론 및 Python/OpenCV/MediaPipe/GStreamer 실행 환경을 확인한다. 현재 Mac 저장소에는 모델 파일이 없다. 함께 다운로드된 `pose_landmarker_full.task`는 현재 게임 판정에 필요하지 않다. 화면은 `2026.10.18/mp_hand.py`의 `cv2.imshow()` 흐름을 이어받아 영상 위·아래에 정보 띠를 붙이고, 한글은 Pillow와 프로젝트에 포함한 Noto Sans KR 폰트로 그린다.
3. 실습 코드의 USB `v4l2src` 파이프라인으로 현장 카메라를 시험하고, 프레임을 시계방향 90° 회전해 출발·제시·손 대기 영역이 위→중앙→아래로 한 화면에 들어오도록 위쪽 지지대를 고정한다. 장치 경로와 영상 형식은 실제 결과에 맞게 조정한다.
4. 공 색별 마스크와 외곽선 검출을 완성하고 색마다 가장 큰 외곽선 하나를 선택한다. 조명·배경에서 공보다 큰 같은 색 물체가 선택되지 않는지 확인한다. MediaPipe의 손목·손가락 뿌리 랜드마크로 양손의 손바닥 상자를 만든다. 실제 사용자 기준 왼손·오른손 보정과 공 중심의 제시 영역·손바닥 상자 포함 판정을 검증한다. 기존 실습 코드의 무조건적인 레이블 뒤집기를 그대로 쓰지 않으며, 손가락 수·관절 각도 계산은 게임 판정에 넣지 않는다.
5. 실제 관측에 따른 판정이 안정화된 뒤 OpenCV `cv2.KalmanFilter`로 색별 추적과 예측 시각화를 추가한다. `2026.10.18/pingpong_kalman_filter.py`의 직접 작성한 필터를 그대로 옮기지 않는다.
6. 기록, 오류 메시지, 재시작, 종료, README 실행법 및 시연 자료를 완성한다.

## 예정 코드 구조

현재 코드는 `contracts.py`, `game.py`, `vision.py`, `main.py`와 테스트 폴더다. 파일 역할은 다음과 같다.

- `main.py`: 카메라 읽기·반복문·화면 표시·종료. 기존 실습 흐름을 확장한다.
- `vision.py`: 공·손 검출과 선택형 색별 추적 함수.
- `game.py`: 문제·준비·판정·시간·점수를 다루는 일반 함수.

`main.py`의 읽기 스레드는 잠금으로 최신 프레임·번호·읽은 시각만 전달하고, 모델·관측·화면은 메인 반복문에서 처리한다. 관측 `Frame`을 `game.update_game`에 전달하고 실패·입력 없음에도 상태와 결과 표시 시간을 갱신한다. 모델 추론 중단 대응은 실제 동작을 확인한 뒤 필요하면 별도 논의한다.

설정값은 사용하는 파일 위쪽의 일반 변수로 시작한다. 화면·카메라·추적·설정을 각각 파일로 나누는 것을 필수로 요구하지 않는다. 실제로 코드가 길어져 분리가 필요할 때 사용자와 이유를 확인한다. 게임 규칙을 단순화하거나 생략한다는 뜻은 아니다.
