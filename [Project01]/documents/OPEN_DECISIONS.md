## 재심사 확인 현황

### 문서와 기존 코드에서 확인함

- [x] 라운드마다 공 3개와 양손의 준비 조건을 확인한 뒤 **3초 카운트다운**, 플레이 제한 **10초 고정**, 성공 +1점·확정 오답/시간 초과 시 기회 -1 규칙이 문서에 일치한다.
- [x] 두 손의 공 2개와 출발 영역에 남은 공 1개를 **같은 채점 프레임에서 실제 검출**해야 한다. 보이지 않는 공은 Kalman 예측으로 채점하지 않는다고 문서에 명시했다.
- [x] 21점 큰 `hand_box`는 후보 필터, 손목·손가락 뿌리의 작은 `palm_box`는 최종 위치 기준이다. 작은 상자는 큰 상자에 포함되므로 두 검사는 독립적인 접촉 증거가 아니다. 손가락 펴짐은 채점하지 않는다.

- [x] 사용자 제공 모델 설치·다운로드 명령과 Jetson의 배치 경로를 기록했다. 저장소에 모델 파일이 없고 Jetson의 파일·로딩·추론은 직접 확인하지 못했다.
- [x] 기존 `mp_hand.py`는 좌우 손 레이블을 무조건 반전한다. 새 게임에서는 이 처리를 그대로 쓰지 않고 실제 양손 보정 결과로 결정하도록 규칙에 적었다.
- [x] 정답·오답 판정의 **유효 프레임**을 각각의 완성 조건이 성립한 정상 입력 프레임으로 정의하고, 누락·조건 이탈·0.15초 초과 간격에서 연속 기록을 초기화하도록 규칙 문구를 보완했다.

## 검토 결과

- **기획의 중심은 일관된다.** 한 사람의 물리적 왼손·오른손에 서로 다른 색 공을 연결하고, 제시 공 2개와 출발 영역에 남은 공 1개가 실제 프레임에 관측될 때만 정답으로 인정한다. Kalman 예측을 채점에 쓰지 않는다는 제한도 기획서와 규칙서에 일치한다.
- **수업 프로젝트 주제와의 연결은 확인된다.** `../../02_Computer-Vision.ipynb`의 Section Project 설명은 이미지 조정·색공간 변환·Image Enhancement·필터링·색상 분할·외곽선 검출·객체 추적·신체 인식 및 신체와 객체 관계의 표현을 요구한다. 계획서는 각 기술의 역할을 적었다. 다만 CLAHE·블러는 시험 후 기본 적용 여부를 정하도록 되어 있고, 구현은 아직 없으므로 **모든 기술을 실제로 활용했다고 판단할 수 없다.**
- **사용자가 점수·기회 규칙을 구체화했다.** 성공 +1점, 완성된 제시 자세에서 안정적으로 확인된 오답 또는 시간 초과 시 기회 -1, 기회 0에서 종료다. 오답 판정 시간과 미완성 장면의 처리 방식은 오검출 방지를 위한 설계 제안이며 현장 시험이 필요하다.
- **기존 실습은 출발점일 뿐이다.** `../../2026.10.18/`에는 단일 초록 공 검출·추적과 손 인식 코드가 따로 있다. 3색 공과 두 손의 연결, 상태 전이, 채점이 통합되어 동작한다는 증거는 없다.
- **평가 비중과 제출 형식은 추가 확인이 필요하다.** 이전 기획서의 30/20/10/30/10% 비중과 README 필수 목차는 이 저장소에서 확인한 Section Project 셀에 없었다. 따라서 현재 기획서에서는 비중을 제거하고 README의 `필수` 표현을 뺐다. 별도 과제 안내를 확인해야 한다.

카메라와 공이 아직 없어도 게임 로직 작성은 가능하다. 아래는 구현을 시작할 때 명시할 선택이며, 실제 인식 성능이 검증됐다는 뜻은 아니다.

| 쟁점 | 권고 기본안 | 남은 확인 |
| --- | --- | --- |

### MediaPipe 모델 확보 결정

사용자 제공 정보에 따르면 Jetson에는 아래 명령으로 손 모델과 포즈 모델이 이미 다운로드되어 있다. 이는 **사용자 보고**이며, 이 작업 환경에서 Jetson의 파일이나 실행 결과를 직접 확인한 것은 아니다. 현재 저장소에는 두 `.task` 파일이 없다.

```bash
pip install --no-deps mediapipe
pip install absl-py flatbuffers sounddevice
wget https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/latest/hand_landmarker.task -O src/models/MediaPipe/hand_landmarker.task
wget https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_full/float16/latest/pose_landmarker_full.task -O src/models/MediaPipe/pose_landmarker_full.task
```

따라서 **모델 다운로드 방법과 Jetson 내 배치 경로는 결정됨**으로 처리한다. 경로의 `src/models/MediaPipe` 디렉터리는 다운로드 전에 존재해야 한다. 이 게임의 현재 판정에는 손 랜드마크만 필요하며, 포즈 모델은 다운로드되어 있다는 사실만 기록하고 사용 범위에는 넣지 않는다. Jetson에서 파일 존재·비어 있지 않은지·MediaPipe 손 모델 로딩과 실제 추론이 되는지는 별도 점검 항목이다.

## 구현 기준으로 채택할 제안값

아래는 사용자 구상과 `GAME_RULES.md` v0.11을 바탕으로 **첫 구현 기준으로 채택한 값**이다. 손가락 펴짐 조건은 제거하고 손 전체 상자로 1차 후보를 찾은 뒤 손별 작은 손바닥 상자로 최종 확인한다. 확인되지 않은 수치와 장비 사양은 현장에서 검증한 뒤 바꿀 수 있다.

| 항목 | 현재 제안값 | 판단 |
| --- | --- | --- |
| 점수와 속도 | 성공 +1점, 반응 시간은 별도 기록 | 첫 버전에서 채점이 단순하고 오답 원인 분석이 쉽다. 속도 보너스는 실제 플레이를 본 뒤 검토한다. |
| 공과 문제 | 빨강·초록·파랑 탁구공을 색당 1개 준비하고, 매 문제에 2색 사용. **선택되지 않은 한 공은 채점하는 동안 출발 영역에 실제로 보여야 한다.** | 빨강·파랑은 도색, 초록은 강사에게 요청할 계획이다. 남은 공이 가려지거나 검출되지 않으면 판정을 보류하고, 완성된 제시 자세에서 출발 영역 밖에 실제로 보이면 안정 확인 후 오답 처리한다. 색과 광택은 실제 영상에서 확인해야 한다. |
| 촬영 배치 | 같은 높이의 신발 상자 2개에 각 500 mL 생수병을 넣고 나무젓가락 2개로 작은 카메라를 받치는 방식으로 계획; 원본 화면 왼쪽의 공 출발·중앙 제시·오른쪽 손 대기를 회전 후 위·중앙·아래로 표시 | 실제 조립·카메라 고정·흔들림·회전 방향·화면 좌표·선 길이는 강의실에서 확인한다. |
| 손과 공의 관계 | 왼손·오른손 각각 21개 랜드마크를 감싼 큰 `hand_box`로 공 중심의 손 근접성을 1차 확인하고, 손목(0)과 손가락 뿌리(5·9·13·17)의 작은 `palm_box`로 최종 확인한다. 지정 색 공의 **실제 검출 중심**이 제시 영역과 같은 손의 두 상자를 모두 통과해 하나씩 연결되어야 정답이다. | 큰 상자 15%·작은 상자 10% 여유는 임시값이다. 작은 상자가 큰 상자 안에 있어 두 검사는 독립된 증거가 아니다. 작은 상자에 두 공이 들어오거나 양손 상자가 겹치면 보류한다. 2D 겹침만으로 물리적 접촉은 증명할 수 없다. |
| 한 판의 종료 | 기회 3개로 시작, 안정적으로 확인된 오답 또는 시간 초과 때 감소, 0개가 되면 종료 | 손·공 이동 중 잠깐 틀린 장면을 즉시 오답으로 보지 않는 판정 조건을 제안했다. |
| 시작 카운트다운 | 결과와 관계없이 매 라운드 준비 조건 0.5초 충족 뒤 **3초** | 정답 뒤에도 공을 컵에 돌려놓고 양손을 대기 영역에 둔 다음부터 3초가 시작된다. |
| 시간 판정 | 첫 구현·시연은 매 라운드 **10.0초 고정**. 정답 0.4초·최소 4프레임 연속 확인 | 실제 플레이 시간·성공률·영상 지연을 본 뒤 제한 시간이 점차 짧아지는 난도 조절을 검토한다. 단축 간격·하한은 아직 정하지 않았으므로 현재 규칙에는 적용하지 않는다. 10초 전에 정답 관측을 시작해도 확인이 10초 뒤에 끝나면 시간 초과다. |
| 공 테두리 | **검은색 바깥 테두리 + 해당 공 색의 가는 안쪽 외곽선** | 밝은 탁자·종이컵 근처에서 흰색 테두리보다 분리되어 보일 가능성이 높다. 공 내부는 가리지 않는다. |
| 공 추적 | 색별 OpenCV `cv2.KalmanFilter`로 짧은 가림 동안만 예측 | 0.5초 뒤에는 `lost` 처리하고 재검출 시 색과 위치로 연결한다. 가림 중 예측은 채점에 쓰지 않는다. |
| 화면 배치 | 위쪽 문제·남은 시간, 아래쪽 점수·기회·상태 | 랜드마크는 손가락과 공을 가리지 않는 얇은 선으로 표시한다. |

## 실물 확인 전에는 확정할 수 없는 값

- Jetson이 실제로 Orin Nano인지, `2026.10.18/`의 USB 카메라 파이프라인(`/dev/video0`, YUY2 640×480 30 fps)이 현장 장비에서 열리는지, 실제 처리 프레임률과 지연.
- 계획한 신발 상자·생수병·나무젓가락 거치대의 실제 조립 여부와 안정성·카메라 고정 상태, 짧을 수 있는 USB 선의 실제 길이, 세 구역을 한 화면에 담을 높이. 카메라 무게가 가볍다는 사용자 판단만으로 안정성은 확정할 수 없다.
- 빨강·파랑 도색의 완성 상태, 강사에게 요청할 초록 공의 확보, 공·종이컵·배경의 색 대비, 실제 조명과 반사, 영역 좌표.
- 손바닥을 오므렸을 때 손 레이블·손목/손가락 뿌리 랜드마크·공을 동시에 안정적으로 관측할 수 있는지, 큰 `hand_box` 확장 15%와 작은 `palm_box` 여유 10%의 오판 빈도. 손가락 펴짐 판정은 요구하지 않는다.
- 손의 왼손·오른손 분류 점수 임계값 0.70, 정답 연속 0.4초·최소 4프레임·최대 간격 0.15초, 예측 표시 0.5초, 입력 장애 0.5초, 라운드 제한 10.0초의 적절성. 0.70은 현장 영상에서 좌우 판정 오류를 보고 조정한다. 느린 장비에서는 0.15초 간격 제한 때문에 성공 자체가 어려울 수 있다.
- 양손을 대기 영역에 두는 시작 조건이 자연스러운지, 손 교차·회전·재등장 시 좌우 보정이 안정적인지.
- 검은 바깥 테두리가 실제 배경에서 충분히 보이는지, 가림 뒤 공 재검출·추적 연결이 안정적인지.
- 카메라 중단·가림·반대 손 제시·세 번째 시간 초과를 포함한 한 판의 실제 재현 결과. 체크리스트의 설계·기록 완료 표시와 별도로 실제 동작·성능은 아직 확인되지 않았다.

사용자가 예정한 **토요일 10시 강의실 점검**에서 `IMPLEMENTATION_CHECKLIST.md`의 장면별 **예상 결과와 실제 결과**를 기록한다. 토요일의 정확한 날짜와 강의실 환경은 문서로 확인되지 않았다. 변경한 수치와 판정 방식은 `GAME_RULES.md`, 설정 파일, README에 함께 반영한다.
