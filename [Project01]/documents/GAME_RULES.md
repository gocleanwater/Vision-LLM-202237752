# 게임 규칙 및 기능 명세 — v0.14

상태: **게임 규칙 v0.14** · 2026-10-23. 제시 영역과 손바닥 상자로 손 위의 공 후보를 판정한다. 사용자 결정에 따라 문제는 매번 6가지 조합 전체에서 무작위로 뽑으며 같은 문제가 연속으로 나올 수 있다. 게임 연결·한글 화면·선택형 추적 코드를 추가했으며, 실제 관측·화면·장비 검증은 미수행이다. 수치는 실물 시험 후 변경 가능하다.

## 1. 용어와 좌표

| 용어 | 정의 |
| --- | --- |
| 물리적 왼손·오른손 | 화면의 좌·우 위치가 아닌 **플레이어 본인의 손** |
| 출발 영역 | 시계방향 90° 회전한 세로 화면의 위쪽에서 뒤집은 종이컵 3개 위에 공을 두는 영역 |
| 제시 영역 | 세로 화면 중앙에서 두 손바닥과 공을 보여주는 영역 |
| 손 대기 영역 | 세로 화면 아래쪽에서 두 손을 놓고 시작하는 위치. 준비 조건에는 포함되며 채점 영역은 아님 |
| 관측된 공 | 현재 프레임의 색상 마스크와 외곽선에서 검출된 공 후보 |
| 손 위의 공 후보 | 실제 검출 공 중심이 제시 영역과 해당 손의 손바닥 상자 안에 들어와, 그 손 위에 있다고 판단한 공. 영상의 2D 위치 기준이며 물리적 접촉을 확정하는 뜻은 아님 |
| 예측된 공 | 마지막 실제 관측을 바탕으로 OpenCV `cv2.KalmanFilter`가 위치를 추정한 공. 관측된 공과 다른 표시를 사용 |
| 반응 시간 | 문제를 포함한 첫 프레임을 `cv2.imshow()`에 넘긴 시각부터 정답 조건이 **처음 연속으로 충족된 프레임**까지의 시간 |

영역은 **시계방향 90° 회전한 영상**의 정규화 좌표 `(x/W, y/H)`로 설정한다. 출발·제시·손 대기의 세 영역은 위→중앙→아래 순서이며 서로 겹치지 않아야 한다. 회전은 카메라 프레임을 받은 직후, 공·손 인식과 영역 판정 전에 적용한다. 화면 미러링을 쓰면 표시와 인식에 일관되게 적용하고, 손 레이블은 실제 왼손·오른손을 각각 들어 확인한 뒤 확정한다.

영역·손 상자의 경계선 위 점도 내부로 포함한다(2026-10-22 구현 계획 승인). 손 상자의 긴 변 기준 여유는 픽셀 공간에서 계산한 뒤 정규화한다. 실제 검출 연결 코드는 추가했지만 실물 좌표·검출 검증은 아직 하지 않았다.

## 2. 장비·세션 기본값

- 위에서 아래로 고정한 USB 카메라 1대, 플레이어 1명, MediaPipe 최대 손 2개. Jetson은 Orin Nano로 추정되지만 모델을 확인해야 한다. `2026.10.18/` 실습의 `v4l2src device=/dev/video0`, YUY2 640×480 30 fps 파이프라인을 첫 시험 설정으로 삼되 실제 동작·속도는 미확인이다.
- 빨강·초록·파랑 탁구공을 색당 1개 준비한다. 빨강·파랑은 도색 예정이고 초록은 강사에게 요청할 예정이다. 실제 색 임계값은 해당 조명에서 보정한다.
- 원본 카메라 화면에서 공 출발·제시·손 대기 영역을 왼쪽→중앙→오른쪽으로 배치하고, 프레임을 시계방향으로 90° 회전해 표시한다. 회전된 화면에서는 출발·제시·손 대기가 위→중앙→아래 순서다. 카메라 화면에는 영역 경계와 이름을 표시한다. 경계 좌표는 회전된 영상에서 현장 보정한다.
- 한 판은 **기회 3개**로 시작하며 라운드 수의 상한은 없다. 성공하면 같은 기회 수로 다음 라운드에 진입한다. 안정적으로 확인된 오답이나 제한 시간 초과 때 기회가 1개 줄고, 0개가 되면 한 판이 종료된다. 첫 구현에서는 모든 라운드의 제한 시간을 **10.0초로 고정**하고, 결과와 관계없이 매 라운드 시작 전 **3초 카운트다운**을 사용한다. 실제 플레이를 본 뒤 제한 시간이 점차 짧아지는 난도 조절을 검토하며, 단축 간격·하한은 아직 정하지 않는다.
- 성공·오답·시간 초과 결과는 **1.5초** 표시한다. 기회가 남으면 이후 준비 안내를 띄우고, 공 3개와 양손이 제자리로 돌아와 준비 조건을 충족할 때까지 기다린다. 1.5초는 첫 구현용 설정값이며 실제 화면에서 읽기 쉬운지 확인한다.
- 정답 관측이 **0.4초 연속** 유지되고 그 사이 유효 프레임이 **4장 이상**이면 확정한다. 유효 프레임 사이 간격이 **0.35초를 초과**하면 연속 기록을 초기화한다. 시간은 단조 증가 시계로 잰다.
- **정상 입력 프레임**은 카메라 읽기와 손·공 관측 처리가 정상 완료된 프레임이다. **정답 유효 프레임**은 정상 입력 프레임 중 7절의 정답 조건이 모두 성립한 프레임, **오답 유효 프레임**은 정상 입력 프레임 중 7절의 완성 자세와 오답 조건이 모두 성립한 프레임이다. 각 연속 기록은 해당 종류의 유효 프레임에서만 늘어난다. 중간의 정상 입력 프레임에서 해당 조건이 깨지거나, 카메라 읽기 실패·모델 예외·유효 프레임 간격 0.35초 초과가 생기면 초기화한다. 정답·오답 기록은 동시에 누적하지 않는다.
- 공의 예측 위치는 마지막 실제 관측 후 **최대 0.5초**까지만 표시한다. 이후 추적 상태를 `lost`로 표시한다.
- 손가락을 모두 펼 필요는 없다. 손바닥을 살짝 오므리는 등 자연스러운 자세로 공을 보여줘도 된다. **실제로 보이는 지정 색 공이 각 손의 손바닥 부근에 하나씩 손 위의 공 후보로 명확하게 보이는지**를 채점한다. 손을 너무 감싸 공이나 손의 위치가 보이지 않으면 판정을 보류한다.

위 값은 사용하는 파일 상단의 일반 변수로 둔다(2026-10-22 사용자 결정). 별도 `config.py`는 만들지 않는다. 실제 카메라 지연과 손 인식 성능을 측정하기 전에는 적정값이라고 단정하지 않는다.

## 3. 문제 생성

1. 매 라운드에서 준비된 색 중 **서로 다른 두 색**을 뽑아 왼손·오른손에 각각 하나씩 배정한다.
2. 문제에 선택되지 않은 **나머지 한 색**을 `남은 공`으로 정한다. 이 공은 해당 라운드의 채점 중 출발 영역에 실제로 보여야 한다.
3. 매번 서로 다른 두 색의 순서 있는 **6가지 조합 전체에서 무작위로 추첨**한다. 같은 문제가 연속으로 나올 수 있다. `PAUSED`에서 복구해 재추첨할 때도 같은 기준을 사용한다.
4. 화면에는 손의 물리적 기준을 명확히 적는다. 예: `내 왼손: 초록 1개 | 내 오른손: 빨강 1개`.
5. 아직 문제가 정해지지 않은 `READY`와 `COUNTDOWN`에서는 **준비한 3색 공 모두** 출발 영역에 실제로 보여야 한다. 하나라도 보이지 않으면 문제를 시작하지 않고 `공 준비 필요`를 표시한다.

## 4. 공·손 관측 데이터

매 프레임의 판정 함수에는 다음 데이터만 전달한다.

- 공 후보: 색, 중심 좌표, 반지름 또는 면적, 실제 검출 여부, 신뢰 가능한 후보 여부.
- 손 후보: 물리적 왼손·오른손 레이블, 랜드마크 좌표, 레이블 신뢰도, 각 손의 `palm_center`·`palm_box`. 손가락 펴짐/굽힘 상태는 채점 입력이 아니다.
- 영역 포함 여부: 각 손의 `palm_center`와 공 중심이 제시 영역에 있는지, 공 중심이 해당 손의 `palm_box` 안에 들어가는지, 그리고 문제에 선택되지 않은 공의 실제 검출 중심이 출발 영역에 있는지.
- 단조 증가 시각과 현재 카메라 프레임 상태.

### 시간 측정 계약

- 실시간 실행은 같은 단조 증가 시계를 사용한다. 문제 화면 제출 시각을 `problem_presented_at`, 프레임 읽기 완료 시각을 `read_at`, 손·공 관측 처리 완료 시각을 `processed_at`으로 구분한다. `read_at`은 실제 카메라 노출 시각이라는 보장은 없다.
- 게임에 관측을 전달할 때 그 프레임의 `processed_at`으로 준비·정답·오답의 연속 시간을 계산한다. 정답 연속 구간이 시작된 최초 `processed_at`을 반응 기록의 끝으로 쓰며, 확인 완료가 제한 시각을 넘었는지도 처리 완료 시각으로 판단한다.
- `read_at`이 해당 문제의 화면 제출 시각보다 이른 프레임은 그 문제의 채점에 사용하지 않는다. 프레임 ID로 같은 결과가 두 번 유효 프레임으로 누적되지 않게 한다.
- 새 관측이 없어도 현재 시각으로 게임·장애 감시·화면·키 처리를 계속 갱신한다. 입력·인식 작업이 게임 루프를 무기한 막지 않도록 분리한다. 마지막 정상 입력은 관측 처리가 완료된 시각으로 갱신한다.
- 반응 기록에는 카메라·인식·표시 지연이 포함되므로 게임 내 반응 시간으로 설명한다. 실제 디스플레이 지연은 현장 검증 사항으로 남긴다.

공 후보는 색별 마스크를 만든 뒤 선택한 모폴로지를 적용하고, `pingpong_circle_overlay.py`처럼 색마다 면적이 가장 큰 외곽선 하나를 선택한다. 최소 면적·형태·원형도·최대 크기 필터는 두지 않는다. 따라서 작은 점 잡음만 남아도 공으로 선택될 수 있고, 같은 색의 더 큰 배경 물체가 마스크에 들어오면 그 물체를 선택할 수 있다. 현장에서 RAW 마스크를 보고 색 범위·배경·모폴로지를 확인한다. 칼만 예측은 화면 표시 및 재연결에만 사용한다.

### 공별 추적 상태

- 빨강·초록·파랑 공마다 OpenCV `cv2.KalmanFilter` 인스턴스를 하나씩 둔다. 첫 실제 검출 중심으로 상태를 초기화한다. 이후 프레임마다 `predict()`를 호출하고, 해당 색 공이 하나로 실제 검출되면 그 중심 좌표로 `correct()`한다. 상태는 화면 좌표 `x, y`와 속도 `vx, vy`, 측정값은 검출 중심 `x, y`를 기준으로 계획한다. 프레임 간 실제 시간 차이를 상태 전이에 반영한다.
- 공이 손에 가려지거나 화면에서 사라져 측정값이 없으면 **예측만** 한다. 마지막 실제 관측 후 최대 0.5초 동안만 `예측` 표시를 하고, 이후에는 `lost`로 표시하며 위치 오버레이를 멈춘다. 공을 빠르게 집어 옮기면 운동 방향이 갑자기 바뀌므로 예측 위치가 실제 공의 현재 위치라는 보장은 없다.
- 공이 다시 보이면 색·후보의 유일성·예측 위치와의 거리 등을 확인해 기존 추적에 연결한다. `lost` 뒤에는 오래된 예측 좌표를 고집하지 않고 새 실제 검출 위치에서 추적을 다시 초기화한다. 0.5초와 재연결 허용 거리는 현장 시험값이다.
- 예측 위치는 **채점, 손 위 공 후보 판정, 출발 영역의 준비 확인에 사용하지 않는다.** 문제에 선택되지 않은 공의 출발 영역 잔류 확인에도 사용하지 않는다. 해당 판단은 그 프레임에서 실제 검출된 공만 사용한다.

## 5. 손 위의 공 후보를 판정하는 규칙

1. 손의 `palm_center`는 손목(0), 검지 뿌리(5), 새끼손가락 뿌리(17) 세 랜드마크의 좌표 평균으로 정의한다. `palm_center`가 제시 영역 안에 있어야 손을 제시한 것으로 본다.
2. **손바닥 상자 `palm_box`**는 손목(0)과 검지·중지·약지·새끼손가락 뿌리(5·9·13·17)의 최소·최대 영상 좌표를 감싸는 직사각형이다. 손바닥이 네모에 가깝다는 직관을 이용한 **2D 근사**다. 손가락 끝 좌표는 넣지 않고, 상자 긴 변의 **10%씩 사방으로 여유**를 준다.
3. 실제 검출 공 중심이 **제시 영역과 해당 손의 `palm_box`** 안에 있을 때만 그 손 위의 공 후보로 본다. 양손의 손바닥 상자에 각 지정 색 공 중심이 정확히 하나씩 있어야 정답이다.
4. 공 중심이 **두 손의 `palm_box`에 동시에** 들어가거나 상자 겹침 때문에 어느 손 위의 공 후보인지 구분할 수 없으면 판정을 보류하고 두 손을 떨어뜨리도록 안내한다.
5. 한 손의 `palm_box`에 서로 다른 공 중심이 둘 이상 들어오면 정답 조건인 `손마다 공 하나`를 충족하지 않는다. 이때 어느 공이 실제로 손에 올려졌는지는 2D 영상만으로 확정할 수 없으므로 즉시 오답으로 차감하지 않고 `모호함`으로 보류한다. 실제 두 공 제시를 오답으로 분류할 별도 기준은 현장 영상으로 검토한다.
6. 손 레이블이 사라지거나 MediaPipe의 왼손·오른손 **분류 점수**가 기본값 **0.70 미만**이면 정답·오답 연속 시간을 모두 초기화한다. 0.70은 임시값이며 실제 카메라 영상에서 점수와 좌우 판정 오류를 본 뒤 조정한다.
7. 실제로 가려져 보이지 않는 공은 추적기가 위치를 예측하더라도 손에 든 공으로 **채점하지 않는다**.

### 손 모양과 관측

- 손가락 개수와 관절 각도는 계산하거나 채점하지 않는다. 손 랜드마크는 손바닥 중심·손바닥 상자 계산과 화면 표시에 사용하며, 물리적 왼손/오른손은 보정한 모델 레이블로 구분한다.
- 손바닥을 조금 오므리거나 일부 손가락을 굽혀도 지정 공이 실제 영상에 보이고 어느 손에 제시됐는지 명확하면 정답이 가능하다. 손이나 공이 가려져 손 위 공 후보가 불명확하면 정답·오답을 보류한다.
- `2026.10.18/mp_hand_rulebased.py`의 손가락 수·160° 관절 각도 규칙은 이 게임의 채점에 사용하지 않는다.

손바닥 상자의 10% 여유는 초기 설정값이다. 공 중심이 손바닥 상자 안에 있어도 물리적 접촉을 증명하지는 않는다. 손바닥을 오므린 자세에서 상자·공 중심이 안정적으로 겹치는지 현장 영상으로 검증한다.

### 왼손·오른손 매핑

화면의 좌·우 위치로 손을 추측하지 않는다. `main.py` 상단의 `HAND_MAPPING`으로 MediaPipe 원시 레이블을 물리적 손에 대응시킨다. 기본값은 `Left→left`, `Right→right`이며 현장 영상에서 표시가 반대로 나오면 매핑 값만 바꾼다. 이 수정은 실행 전 코드 설정이며 게임 시작을 막는 별도 확인 단계는 없다. 촬영 방향·반전 설정을 바꾸면 표시를 보고 같은 값을 조정한다. 실행 중 손 등록·0.5초 보정 대기·Space 확인 절차는 사용하지 않는다.

## 6. 라운드 상태 전이

| 상태 | 화면/동작 | 다음 상태로 넘어가는 조건 |
| --- | --- | --- |
| `SETUP` | 코드에 영역이 아직 없을 때 입력을 기다리는 내부 상태 | `REGIONS`가 설정된 상태에서 첫 정상 프레임 입력 → 자동으로 `READY` |
| `READY` | 완료된 시도 뒤에는 `다음 라운드를 위해 공을 제자리에 두고 손은 손 대기 영역 안에서 대기하세요.` 안내. 첫 라운드와 새 판에서는 `시작하려면 공을 출발 영역에 두고 손은 손 대기 영역 안에서 대기하세요.` 안내. 장애 복구 뒤 같은 번호의 무효 라운드를 다시 시작할 때는 `문제를 다시 시작하려면 공을 제자리에 두고 손은 손 대기 영역 안에서 대기하세요.` 안내 | 3색 공 모두 출발 영역에 실제로 보이고, 양손 손바닥 중심이 손 대기 영역에 있으며, 제시 영역에 공과 양손 손바닥 중심이 없는 조건이 0.5초 유지되면 → `COUNTDOWN` |
| `COUNTDOWN` | 매 라운드 3→2→1 표시 | 공 3개 실제 검출을 포함한 준비 조건이 매 정상 입력 프레임에서 유지되면 종료 시 문제를 만들고, 문제를 포함한 첫 프레임을 `cv2.imshow()`에 넘길 때 시작 시각 기록 → `ACTIVE`; 준비가 깨지면 `READY`로 돌아가 0.5초 준비 확인부터 다시 시작 |
| `ACTIVE` | 문제·남은 시간·손별 공 색상/손 위 공 후보 피드백·점수·남은 기회 표시 | 정답 0.4초 연속 → `RESULT_SUCCESS`; 완성된 제시 자세의 오답 0.4초 연속 → `RESULT_WRONG`; 10.0초 경과 → `RESULT_TIMEOUT`; 연속 입력 공백 0.5초 이상 또는 모델 예외 → `PAUSED` |
| `RESULT_SUCCESS` | `정답!`과 반응 시간 1.5초 표시, 내부 점수 +1, 기회 변화 없음 | 표시 시간이 끝나면 → `RESET` |
| `RESULT_WRONG` | `오답`과 사유 1.5초 표시, 점수 변화 없음, 기회 -1 | 표시 시간이 끝나면 기회가 남을 때 `RESET`, 0이면 `SUMMARY` |
| `RESULT_TIMEOUT` | `시간 초과` 1.5초 표시, 점수 변화 없음, 기회 -1 | 표시 시간이 끝나면 기회가 남을 때 `RESET`, 0이면 `SUMMARY` |
| `RESET` | 이전 문제와 판정 연속 기록을 정리하고 문제 표시를 지움 | 기회가 1개 이상이면 곧바로 `READY`; 기회가 0이면 `SUMMARY` |
| `PAUSED` | 카메라/모델 문제 표시, 활성 시도의 시간 측정 중단 | 입력 회복 후 `READY`에서 재준비. `ACTIVE`에서 중단된 미완료 시도만 무효 처리하며 라운드 번호·점수·기회는 유지한다. 준비 중 장애는 문제 무효 처리 없이 복구한다. |
| `SUMMARY` | 최종 점수(성공 횟수), 시도 횟수, 정답 반응 시간의 평균·최단 기록 | 재시작 입력 시 점수 0·기회 3개로 초기화 → `READY`; 종료 입력 시 닫기 |

점수 증가와 기회 감소는 `RESULT_SUCCESS`, `RESULT_WRONG`, `RESULT_TIMEOUT` 중 하나에 **진입할 때 한 번만** 적용한다. 완료한 시도 횟수는 이 세 결과 중 하나가 확정될 때만 1 증가하며, 현재 라운드 번호는 `완료한 시도 횟수 + 1`이다. 카메라 장애로 무효가 된 시도는 이 횟수에 넣지 않는다.

카운트다운은 결과와 관계없이 매번 `READY`에서 공 3개와 양손 대기 조건이 0.5초 유지된 **뒤에만 3초간** 시작한다. 정답 뒤에도 공을 출발 영역에 돌려놓고 손을 대기 영역에 둔 다음 시작하므로, 정답 직후 3초 안에 준비를 끝내야 한다는 뜻은 아니다.

준비 확인에서 공의 ‘제자리’는 **출발 영역 안**을 뜻한다. 색별 원래 컵 위치나 컵 위에 있는지는 검사하지 않는다. 세 색 모두 유효한 실제 검출 후보가 각각 하나이고, 보정된 물리적 양손이 각각 하나씩 신뢰도 0.70 이상으로 관측되어야 한다. 준비 조건 이탈, 입력 실패, 정상 관측 사이 0.35초 초과 공백이 있으면 준비 유지 시간을 초기화한다. `COUNTDOWN` 중 같은 일이 생기면 `READY`로 돌아가 준비 확인부터 다시 시작한다. 손·공의 가림이나 낮은 손 신뢰도는 준비 조건 미충족이며 카메라 장애 자체를 뜻하지 않는다.

결과 화면의 1.5초가 끝난 뒤에는 문제 문구를 지우고 `READY`의 준비 안내를 표시한다. 플레이어가 두 공을 출발 영역에 되돌리고 세 공 모두가 실제로 검출되며 양손이 손 대기 영역에 들어올 때까지 기다린다. 준비가 0.5초 유지된 뒤 3초 카운트다운을 시작하고, 카운트다운 내내 준비 조건이 유지됐을 때만 **새 문제를 추첨·표시**한다. 오답과 시간 초과 뒤에도 같은 흐름을 적용하며, 마지막 기회가 소진됐으면 결과를 1.5초 보여준 뒤 `SUMMARY`로 간다.

`ACTIVE` 중 양손·공 2개가 제시 영역에 보이고 어느 손의 공인지 명확한 **완성된 제시 자세**에서만 오답 연속 시간을 센다. 문제에 선택되지 않은 `남은 공`도 해당 프레임에서 실제 검출되어 위치가 확인되어야 채점한다. 지정 색과 다른 공을 제시했거나 `남은 공`이 출발 영역 밖에 명확히 보이는 상태가 0.4초·최소 4프레임 유지되면 오답이다. `남은 공`이 보이지 않거나 검출이 모호하면 정답·오답을 모두 보류하고 타이머는 계속 간다. 손·제시 공 누락, 가림, 낮은 레이블 신뢰도, 손 위 공 후보의 모호함도 판정 보류한다. 손가락을 굽힌 것 자체는 오답이 아니다. 이 규칙은 플레이어가 일부러 제시했는지는 판별하지 못하므로, 이동 중에도 완성 조건이 오래 유지되면 오답이 될 수 있다. 정답·오답 연속 시간은 조건이 깨지거나 두 유효 프레임 간격이 0.35초를 넘으면 초기화한다. `PAUSED`에서 복귀할 때는 같은 번호의 라운드에서 3절 기준으로 문제를 다시 뽑고 타이머를 0에서 시작한다.

`cap.read()`가 한 번 실패하거나 유효 프레임 간격이 0.35초를 넘으면 **정답·오답 연속 기록을 모두** 초기화한다. **마지막 정상 프레임 이후 0.5초 이상 입력이 없거나 모델 예외가 발생하면** 입력 장애로 보고 `PAUSED`로 들어간다. 제한 시각에 정상 프레임이 없다면 시간 초과 확정을 잠시 보류한다. 0.5초 안에 정상 입력이 돌아오면 경과 시간을 확인해 시간 초과를 적용하고, 0.5초 이상 끊겨 `PAUSED`가 되면 해당 시도는 기회 차감 없이 무효 처리한다. 따라서 제한 직전에 카메라가 멈춘 경우도 장애 판정을 기다린다. `PAUSED`에서는 정상 프레임과 모델 결과가 회복될 때까지 새 문제를 내지 않는다.

카메라의 짧은 끊김은 **한 번의 연속 입력 공백이 0.5초 미만이면 라운드를 무효로 하지 않는다.** `ACTIVE`의 10초 타이머는 계속 흐르고 판정 연속 기록만 초기화한다. 정상 입력이 돌아오면 장애 감시의 기준 시각을 갱신하므로, 떨어져 발생한 짧은 공백을 합산하지 않는다. 손이나 공만 검출되지 않고 영상·모델 처리가 정상 완료된 프레임은 입력 장애로 세지 않는다. 0.5초는 설정값으로 두고 현장 지연을 보고 조정한다. 모델 실행 예외는 기존 규칙대로 즉시 입력 장애로 처리한다.

### 상태별 입력 장애 처리

아래 규칙은 마지막 정상 입력 이후 0.5초 이상 중단되거나 모델 예외가 발생했을 때 적용한다.

| 장애가 발생한 상태 | 처리와 복구 |
| --- | --- |
| `SETUP` | 입력 오류를 안내하고 정상 입력과 설정된 영역을 받으면 자동으로 `READY`로 이동한다. 코드의 좌우 매핑은 유지한다. |
| `READY` / `COUNTDOWN` | 준비·카운트다운을 취소하고 `PAUSED`로 간다. 무효 처리할 활성 문제는 없으며, 복구 후 `READY`에서 재준비한다. |
| `ACTIVE` | `PAUSED`로 가서 미완료 시도만 무효 처리한다. 복구 후 같은 라운드 번호로 재준비하며 3절 기준으로 문제를 다시 뽑는다. |
| `RESULT_*` / `RESET` | 이미 확정한 점수·기회·시도 횟수·반응 기록을 보존한다. 결과는 예정된 1.5초 동안 표시한다. 기회가 남으면 준비 단계에서 입력 회복을 기다리고, 0이면 `SUMMARY`로 간다. |
| `SUMMARY` | 확정 기록과 요약 화면을 유지한다. 새 판 시작 시 기록을 초기화하고 다음 정상 프레임에서 준비를 시작한다. |

`PAUSED`는 진입 전 활성 문제가 있었는지 기억한다. 활성 문제가 없는 준비 중 장애를 라운드 무효로 집계하거나, 확정 결과를 취소하지 않는다. 카메라 입력이 없는 동안에도 오류 안내·타이머 감시·종료 키 처리가 가능하도록 게임과 화면 루프를 유지한다.

## 7. 정답·시간·점수

정답은 같은 시간 구간에 다음 조건을 **모두** 만족할 때만 확정한다.

1. 물리적 왼손과 오른손이 각각 하나씩 검출되고 레이블이 보정된 기준과 일치한다.
2. 양손의 손바닥 중심이 제시 영역에 있고, 두 `palm_box`가 공이 어느 손 위에 있는지 모호하게 만들 만큼 겹치지 않는다. 손가락을 펴거나 굽힌 정도는 조건이 아니다.
3. 제시 영역과 각 손의 `palm_box` 안에 들어온 손 위 공 후보의 **실제 관측 공 중심**이 정확히 하나이며, 왼손·오른손의 색이 각각 문제와 일치한다.
4. 문제에 선택되지 않은 **남은 색 공 1개가 같은 프레임에서 실제로 검출되고, 그 중심이 출발 영역 안에 있다.** 추적 예측이나 이전 프레임 위치는 인정하지 않는다.
5. 위 조건이 0.4초 이상, 유효 프레임 4장 이상 유지되고 연속 유효 프레임 간격이 매번 0.35초 이하다.

**오답 확정 조건:** 양손의 손바닥 중심이 제시 영역 안에 있고, 각 손의 `palm_box`와 제시 영역 안에 있는 실제 관측 공 중심이 정확히 하나씩 손 위의 공 후보로 명확하게 보이며, 두 손 레이블과 `남은 공`의 실제 위치가 확인되는 **완성된 제시 자세**에서 지정 색 불일치 또는 `남은 공`의 출발 영역 이탈이 0.4초·최소 4프레임 연속 유지될 때다. 손·공 누락, 가림, 손 위 공 후보의 모호함이나 `남은 공`의 검출 실패는 오답으로 확정하지 않는다. 손가락 모양은 오답 사유가 아니다. 정답과 오답 조건은 상호 배타적이다. 0.4초 유지가 의도적인 제시를 증명하지는 않으므로 현장 동작 시험에서 오차감을 확인한다.

라운드 성공은 **+1점**, 오답 확정 또는 제한 시간 초과는 **점수 변화 없음·기회 -1**이다. 시작 기회는 3개이며 성공해도 기회는 회복되지 않는다. **기회 3개가 모두 소진될 때까지가 한 판**이고 점수에 상한은 없다. 반응 시간은 문제 프레임을 `cv2.imshow()`에 넘긴 시각부터 정답 조건을 충족하기 시작한 최초 시각까지 기록하므로, 0.4초 확인 대기 시간은 기록에 더하지 않는다. 이 시작 시각은 실제 디스플레이 표시 시각과 차이가 날 수 있다. **성공·오답 확인이 10.0초 제한 시각에 완료되지 않았다면 시간 초과가 우선**한다. 요약 화면의 평균 시간은 **성공 라운드만** 사용하고, 성공이 없으면 `기록 없음`으로 표시한다. 시간 비교는 같은 카메라·설정 환경에서만 의미 있게 해석한다.

### 화면 표시

- 회전된 카메라 영상, 위쪽 정보 띠, 아래쪽 정보 띠를 너비가 같은 **한 장의 이미지**로 합쳐 `cv2.imshow()` 창 하나에 표시한다. 정보 띠의 한글은 Pillow와 한글 폰트로 그린다. 화면 연결 코드는 구현했으며 실제 Jetson 화면·실물 촬영 결과는 미검증이다.
- 카메라 영상 **위쪽**에 현재 문제(`내 왼손: 초록 | 내 오른손: 빨강`)와 남은 시간을 표시한다.
- 카메라 영상 **아래쪽**에 현재 점수, 남은 기회 `3/3`과 아이콘 3개, 상태(`준비 중`·`채점 중`·`정답`·`오답`·`시간 초과`)를 표시한다. 오답이면 짧게 사유도 표시한다.
- `ACTIVE`에서는 남은 색 공이 출발 영역에 실제로 확인됐는지도 표시한다. 확인되지 않으면 `남은 공 확인 필요`, 출발 영역 밖에 명확히 보이면 `남은 공 위치 오류`로 안내한다.
- 출발·제시·손 대기 영역의 경계는 얇은 선과 이름으로 표시한다. 영역 좌표는 카메라 설치 후 설정한다.
- 빨강·초록·파랑 공에는 **검출된 현재 위치의 외곽선** 해당 공 색으로 표시한다. 가시성을 위해 같은 외곽선을 **검은색 굵은 선으로 먼저**, 그 위에 **공 색의 가는 선으로 다시** 그려 검은 바깥 테두리가 보이게 한다. 2026-10-23 사용자 요청에 따라 실습의 흐름처럼 내부에 15% 반투명 색을 겹치고 최소 외접원·중심도 표시한다. 추적 예측 위치는 회색 십자·빈 원과 `predicted` 표기로 실제 검출과 분리한다.
- 손 랜드마크는 얇은 선·작은 점과 물리적 왼손/오른손 레이블로 표시한다. 공을 가리지 않도록 선 굵기·색을 조정하고, 각 손의 공 색상·손 위 공 후보의 확인 또는 미확인 상태를 표시한다. 손가락 `5/5` 표시는 사용하지 않는다.
- 각 손의 `palm_box`는 공과 손을 가리지 않는 가는 청록 점선으로 표시한다.

## 8. 예외와 공정성

- 손 하나만 보이면 `다른 손을 보여주세요`를 표시하고 계속 시간을 잰다. 이 상태만으로 기회를 차감하지 않는다.
- 손가락을 굽힌 자세도 허용한다. 양손·제시 공 2개·남은 공의 실제 위치·손 레이블과 손 위 공 후보가 모두 명확한 완성 자세가 아니면 오답 연속 시간을 누적하지 않는다. 완성 조건이 0.4초 유지되면 이동 의도와 무관하게 오답이 될 수 있다.
- 손 레이블이 바뀌거나 신뢰도가 낮으면 `손 구분 확인 중`을 표시하고 그 구간은 정답으로 누적하지 않는다.
- 공이 손이나 다른 물체에 가리면 예측 위치만 별도 스타일로 표시한다. 예측 중인 프레임은 정답으로 누적하지 않는다.
- 공이 같은 색의 배경·옷과 혼동되거나 유효 후보가 여러 개면 해당 색은 미확인 처리한다.
- 프레임이 빠지면 0.35초 간격 규칙에 따라 정답·오답 연속 기록을 모두 초기화한다. 제한 시간은 실제 경과 시간으로 처리하며, 제한 시각에 입력이 없는 경우는 6절의 장애 우선순위를 따른다. 카메라 입력이 지속해서 끊어지면 점수나 기회를 바꾸지 않고 현재 시도를 무효 처리하며, 라운드 번호는 유지한다.
- 화면을 좌우 반전해 보여주는 경우에도 채점 기준은 항상 **플레이어의 실제 왼손·오른손**이다. 화면상 왼쪽 손이라는 뜻이 아니다.
- `q`로 종료, `r`로 새 판 시작을 제공한다. 새 판은 누적 점수·반응 시간·시도 횟수를 초기화하고 기회를 3개로 되돌린다. 다음 정상 프레임에서 코드에 설정된 영역을 사용해 자동으로 `READY`로 이동한다.

## 9. 검토 또는 실물 시험 후 확정할 값

1. USB 카메라 지지대의 안정성·선 길이, 출발·제시·손 대기 영역의 실제 위치, 세 영역을 한 프레임에 잡을 수 있는 구도.
2. 도색한 빨강·파랑 공과 확보할 초록 공을 실제로 구별할 수 있는지, 공 표면의 광택·컵·배경 영향.
3. 손바닥을 살짝 오므린 상태에서도 손바닥 중심·물리적 왼손/오른손 레이블과 공 색·위치가 함께 안정적으로 관측되는지. 손으로 공을 완전히 가리면 현재 규칙으로 채점할 수 없다.
4. 0.4초 정답·오답 유지, 0.5초 예측 표시, 10초 제한이 실제 Jetson 프레임률·지연에서 적절한지.
5. 사용자가 손에 공을 올려 **보이는 상태로 제시**하는 동작이 자연스럽고 반복 가능한지. 영상만으로 물리적 접촉 자체를 증명할 수는 없다.

이 항목들은 사용자가 예정한 토요일 10시 강의실 장비 점검에서 확인한다. 현재 규칙은 `v0.14`이며, 현장 적정성과 실제 장비 동작은 미검증이다.
